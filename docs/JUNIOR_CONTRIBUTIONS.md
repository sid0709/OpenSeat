# Junior contribution rules

Tracked policy: [issue #2](https://github.com/sid0709/OpenSeat/issues/2).

1. Start with an assigned product issue and a small branch from main.
2. Ask the existing owner for design feedback before changing shared APIs.
3. Add behavior tests, follow the coding style, and explain the change in the PR.
4. Never bypass checks or merge your own unreviewed work.
5. Infra, authentication, CI, dependencies, release tooling, and shared-platform
   changes require senior/platform review. Maintainers must designate that reviewer;
   a contributor title alone does not grant approval authority.
6. Escalate unclear requirements or failures in the issue/PR. Include reproduction
   steps and sanitized logs. Do not commit credentials or production data.

See [contributing](CONTRIBUTING.md) for required checks and approval counts.
